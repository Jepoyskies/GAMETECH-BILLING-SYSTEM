# SYSTEM SPECIFICATION: DISPATCH OPERATION & AGENT ONBOARDING

FLOW: Agent or walk-in -> policy checklist -> customer (Pending Install) + job order -> Dispatch assigns technicians by team (technicians never self-pick) -> technician Arrived (timer) -> Done + report -> Dispatch QA (reviews time/date/problems, calls the customer) -> Admin final approval (only 3 admins). Bounce-backs: Admin->Dispatch, Dispatch->Technician, reason required, full history visible to Admin. Installs use the full flow; repairs skip admin approval unless bounced twice or flagged; Site Visits go assign->done.
AREAS/ACCENTS: Customers/Billing blue, Dispatch Operation violet, Cignal Play red. Dark and light themes must both work; use shared design tokens/components.
DECISIONS:
1 Checklist is always the first step of adding a new-install customer (walk-in and agent referral), enforced server-side; items: free installation; the customer's plan (name and price); no lock-in period; staggered payments (agent-referred: not available for 60 days from first payment; walk-in: available); repair within the day; rebates within 24 hours. Methods: in person or phone. Declines are recorded with reason; no customer created. Flow: checklist -> customer form -> one atomic submit creating customer + job order.
2 Walk-in: staff use Add Customer after the checklist. Customer counts as disconnected until installed.
3 Agents create only PROSPECTS (own login, or staff on their behalf). Staff get a bell notification, run the checklist, create the customer prefilled with the agent linked.
4 Agent portal: minimal mobile layout, no staff access; short prospect form; own referrals list showing only name, status, payment progress, due date (no contact details); edit until staff open it; duplicate detection on phone or name+address; first submission keeps credit.
5 First payment: after tech marks Done, staff see "connected but unpaid" (existing PPPoE detection), record the first payment via Renew/Pay Bill; existing logic activates. First payment date = install date; starts billing clock and the 60-day lock. QA/admin approval never gate activation.
6 Staggered lock: the 3-day/15-day/custom options are disabled for agent-referred customers for 60 days from first payment date (server-side); custom amounts must be at least one monthly price during the lock.
7 Incentive: PHP 500 per referred customer whose SECOND month is paid (later payment, or 2+ month advance; partial payments accumulate to 2x monthly price; one-time fees excluded). Cancelled-before-qualifying never counts; qualified stays counted unless the qualifying payment is rolled back before payout. Cash out PHP 2,500 per 5 qualified (multiples ok, oldest first); counter resets after payout, extras carry over; history permanent (every customer linked to the referring agent forever; every qualification and payout batch kept with who/when). Values are settings. Counts only customers created through the new flow.
8 Agent changes need a permission and logged reason; original agent always preserved.
9 Roles: Agent, Staff, Dispatch, Technician, Admin; permission-based via the existing mechanism; one person may hold any combination.
10 Same-person rule: do not block; record the actor of every stage and flag jobs where one person handled 2+ stages; show to admins.
11 Bounce-backs need a reason and a type (revisit with new timer / correct report); admin summary of patterns (by user, stage, reason, same-person flags); alert after 2 bounces on a job.
12 Client unreachable: technician logs each call attempt; after 3 attempts (or a refusal) returns the job to Dispatch; Dispatch informs the agent; close reasons Undecided / Change of mind / Unreachable / Other; must tick "client and agent informed"; customer becomes "Closed - Not Installed" (excluded from lists, counters, expiry, incentives); if the client returns, reuse the record with a new job order and run the checklist again; credit goes to the agent who submits the new ticket. Unreachable returns are tracked separately from quality bounces.
13 Technicians: mobile-first, see only assigned jobs; Arrived starts timer, Done stops it, then report; dispatch can correct a forgotten timer with a logged reason; marking Done notifies staff.
14 Assignment: team-based picker, off-duty marking.
15 Notifications (reuse bell): prospect submitted, tech Done, bounce-backs, repeated-bounce alert, job returned unreachable.
16 Add a real Site Visit ticket type (assign->done). 17 One central ticket-number generator.
18 Welcome SMS on FIRST payment via the existing SMS wrapper and message-template editor: new tags {portal_username} {temp_password} {portal_address} (plain text, no links); generate a fresh random hashed temporary password at first payment, show it once on the payment-success screen too; mask it in SmsLog.
PHASES: 0 safety net; 1 security/logins (hashed portal passwords, password policy, lockout, HTTPS prep); 2 foundation models/permissions; 3 checklist/prospects/agent portal; 3.1 fixes; 3.2 router safety and guard fixes; 4 dispatch operation; 5 billing integration and incentive engine; 6 UI unification in dark/light; M legacy billing database import (separate track, later).

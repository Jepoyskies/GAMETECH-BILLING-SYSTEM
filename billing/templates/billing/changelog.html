Zero-Downtime Router Transfer & Hardware Replacement Architecture

Solved the critical field maintenance challenge where migrating subscribers between Mikrotik routers for scheduled router swaps caused immediate subscriber disconnection before the hardware was physically replaced:

  • The Problem: When updating a customer's router assignment or performing a Sync Manager move, Django's post-save signal executed "Orphan Cleanup" on the old router using delete_pppoe_user(). By default, secret deletion also forcefully kicked the subscriber's active session, abruptly severing their internet connection while the old router was still in service.
  • Decoupled Session Lifecycles: Upgraded network_manager/services/users.py to accept a kick_active=True/False parameter. In billing/signals.py, orphan cleanup now runs with kick_active=False.
  • Zero Service Interruption: The old PPPoE secret is removed (preventing future logins), but the established active PPPoE interface session remains fully connected and operational on Router A until field technicians physically swap the hardware, at which point the ONT authenticates smoothly onto Router B. Documented in gametech_error_runbook.md under ERR-018.

September 10, 2026: Live Monitoring Recovery, Network Engine Extraction & Aider Sniper Architecture

Live Monitoring & Router Uplink Telemetry Fix

Live Monitoring and router ping latencies had stopped polling and failed to display uplink metrics. A deep investigation uncovered two root causes and applied permanent fixes:

  • Missing Select2 Dependency: The router selection dropdown required jQuery Select2, which was absent from live_monitoring/_scripts.html. This threw a fatal unhandled JavaScript exception ($().select2 is not a function) that halted script execution before the live polling timer could even start. Added the required Select2 JS/CSS assets and safeguarded the initialization with a fallback check.
  • Resilient Ping Parsing: In billing/views/api/network.py, ping RTT regex parsing assumed integer millisecond values, throwing ValueError exceptions when Mikrotik returned sub-millisecond or decimal response times (e.g. 12.4ms). Upgraded regex and type-casting to gracefully parse floating-point RTTs.
  • Immediate Polling Loop: Changed startInterval() to trigger a cycle immediately on page load rather than waiting for the initial 5-second interval delay, making uplink status appear instantly.
Shared Network Telemetry Architecture (NetworkMonitor)

Extracted repetitive and scattered router polling routines into a clean, reusable standalone module:

  • Module Creation: Created static/js/network_monitor.js providing a unified NetworkMonitor class to handle pinging, uptime tracking, signal strength polling, and error recovery across all pages.
  • View Customer Script Overhaul: Repaired a truncated syntax error in billing/templates/billing/view_customer/_scripts.html, integrated modern SweetAlert2 confirm modals for customer actions, and hooked into NetworkMonitor for continuous connection telemetry.
Dashboard Caching & Timezone Hardening (500 Error Resolution)

Diagnosed a recurring 500 Internal Server Error when staff navigated back to the dashboard or refreshed cached pages:

Rebates — Mikrotik-Aware Free Day Extension

Rebates are applied when a customer's internet was not repaired within 24 hours (SLA breach). The rebate system was upgraded to:

  • Extend the customer's expires_at by the rebate amount (days or hours)
  • Dynamically flip customer status to active if they were expired/suspended, or keep active if still within their billing period
  • Background SLA task (auto_process_sla_rebates via Celery) now autonomously restores internet for customers whose SLA ticket was open when they expired — they are revived without staff intervention
  • The post_save signal in billing/signals.py detects the status change and pushes enable/enable-profile/kick commands to the Mikrotik router, preventing free surfing
  • Manual rebate view also updated with same Mikrotik sync logic
Rollbacks & Transfer Reverts — Full Mikrotik Sync

Rollback is used when a payment was entered incorrectly and needs to be reversed. Transfer Revert is used when a payment was transferred to the wrong customer. Both were updated to:

  • Revert expires_at to the previous value stored in the Payment record
  • Dynamically evaluate whether the reverted date is in the future or past — setting status to active or expired accordingly
  • The status flip triggers the post_save signal which syncs the Mikrotik router (suspend or reactivate as needed)
  • expires_at field change was added to the signal monitor so any expiration date change (not just status) triggers a re-evaluation
  • All operations wrapped in transaction.atomic() with select_for_update() to prevent race conditions
Live Monitoring — Multi-Tiered Architecture

The Live Monitoring page was enhanced from a simple system summary into a multi-level monitoring dashboard:

  • Overall View: System-wide summary of all Mikrotik routers (online/offline), total active PPPoE sessions, bandwidth stats
  • Per-Router View: Click any router to see its individual metrics — connected users, upload/download speeds, uptime, active PPPoE sessions list
  • Per-Customer View: Staff can inspect any individual customer's real-time status without leaving the monitoring page
  • Detection fixes: Router speed and upload/download now correctly pull from the /interface/monitor-traffic API endpoint
  • Router online/offline detection fixed — uses connection timeout as the primary indicator
Payment Confirmation — Notification Toggles

Before confirming a payment, staff can choose whether to dispatch alerts to the customer:

  • Two toggle switches added to the payment modal: Send SMS Notification and Send Email Notification — checked by default
  • Unchecking either switch prevents that delivery channel from firing
  • The backend pay_customer_view reads these POST values and conditionally calls Semaphore SMS or Django send_mail()
  • SMS and Email audit logs are still preserved regardless of dispatch choice

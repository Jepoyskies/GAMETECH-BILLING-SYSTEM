August 29, 2026 (Core Backend Refinements & AI Tracking) Latest Build

AI Development Tracking System

We established a permanent AI Development Archiving System. All implementation plans, walkthroughs, task checklists, and architectural decisions generated by the AI agent from August 11 to the present are now strictly saved as Markdown (.md) documents inside a dedicated docs/ai_tracking/history/ directory in the core repository.

This guarantees that even if the AI's short-term memory is wiped or a new session is started, it can simply read the ai_tracking directory to regain full context of the entire Gametech Billing System source code structure and history.

Admin Activity Tracker (ActiveUserMiddleware)

We abandoned simple "last login" tracking and engineered the ActiveUserMiddleware. This middleware utilizes an incredibly fast Redis Cache Server to record the precise timestamp of every single page request made by an authenticated admin, throttled dynamically to 60 seconds to prevent server overload.

The dashboard's Recent Admin Logins widget now taps directly into this cache, parsing the activity timestamps in a beautifully formatted 12-Hour AM/PM format (e.g., 2:30 PM instead of 14:30), complete with "X minutes ago" logic. Sir Romnick can now definitively see who is actively clicking through the system in real time.

The System Encyclopedia UI

We discarded the small dropdown changelog and developed this exact full-screen page—the Complete System Development Encyclopedia. It was built specifically so administrators and stakeholders could scroll through a hyper-detailed architectural log of exactly what was built on what day, down to the exact variables and logic layers used.

August 28, 2026 (Sync Manager V2, Fixes, & Payment Logistics)

Sync Manager V2: Suspicious User Detection

The Sync Manager was utterly transformed into an advanced security auditing utility. We programmed it to pull all PPPoE secrets directly from the router and instantly cross-reference them against the local Django SQL database, sorting them into three strict tiers:

  • Active Users: Perfect matches. The customer exists in both databases.
  • Clean Imports: Accounts that exist on the router but not locally, and have valid profiles assigned. Ready for safe importation.
  • Suspicious / Rogue Users: The system actively hunts down and flags any PPPoE accounts that are using the 'default' unlimited profile, missing required comments, or exhibiting malicious account names. This is Gametech's automated defense against rogue technicians.

Winbox Hygiene: We added an automation hook that forces the Mikrotik's PPPoE Comment field to auto-update exactly as Full Name | Barangay the moment a staff member updates a profile in Django. No more messy routers.

Payment Staggering & Transfer Engine

A massive update to the core financial controller (PaymentView). The logic was expanded to handle complex Staggered (Partial) Payments.

  • Fractional Logic: If a customer pays exactly 37% of their monthly bill, the system's algorithm translates that directly into a 37% extension of their active days (down to the hour).
  • Quick Pay Grid: Built a specialized UI module inside the Customer Profile with one-click buttons to automatically split the user's monthly due into exact halves or quarters, removing the need for staff to manually type in cash denominations.
  • Payment Reversals & Transfers: Mistaken payments are no longer permanent. An Admin can now click "Transfer" on a rogue log, assign it to a new customer, and the system autonomously executes a perfect mathematical rollback of Customer A's expiration date while safely extending Customer B's date.
Mikrotik Bridge Filter Bug Demolition

Resolved a severe bug where suspended customers were not coming back online after making a payment. The API logic was failing to locate and destroy the dynamic 'Drop' rule inside the Mikrotik's IP Firewall Filter. The code was rewritten to hunt down rules based specifically on the user's IP Address and destroy them instantly upon reactivation.

Intelligent Customer Sorting & Color Coding

The core Customer List (CustomerListView) was completely re-architected. Previously, it simply sorted by ID. We applied a complex Django QuerySet annotation to sort accounts by priority of urgency:

1. Active → 2. Pending → 3. Suspended → 4. Expired → 5. Inactive → 6. Pull Out

We also injected raw CSS targeting into the HTML tables to visually colorize rows: Amber for Expired, Gray for Suspended, and Red for pulled out. This allows collections agents to fly through the list visually.

August 24 - 26, 2026 (Live Production Deployment & Monitoring)

Live Production Deployment Architecture

This was the most critical phase. We ripped the system out of the local development environment and deployed it to a globally accessible live production environment.

  • DigitalOcean Linux Droplet: Provisioned a powerful, dedicated cloud server running Ubuntu.
  • Docker Containerization: We wrote a docker-compose.yml file to containerize the Django Application, Gunicorn WSGI Server, and the Redis Cache. This ensures that if the Python app crashes, the container instantly reboots itself safely.
  • Nginx Reverse Proxy: Hand-coded an nginx.conf file to act as the primary traffic cop, handling incoming HTTP requests, managing SSL/TLS logic, and seamlessly serving static assets (CSS, JS, Images) bypassing Django entirely for extreme speed.
  • Automated CI/CD via GitHub Actions: We built a CI pipeline (.github/workflows/deploy.yml) so that anytime we run git push origin main, GitHub autonomously SSHs into the DigitalOcean server, pulls the new code, rebuilds the Docker images, and restarts the system seamlessly.
Live Monitoring & Auto-Diagnostics Dashboard

To give administrators god-like visibility, we built the Live Monitoring dashboard which acts as the network's nerve center.

  • Router Uplink Tracker: The backend aggressively pings the Mikrotik API. If the router loses internet or power, the dashboard immediately triggers a massive red "Network Outage" alert on the main screen.
  • Offline User Diagnostics: If a customer goes offline, the system cross-references all other customers assigned to the exact same Barangay. It uses basic associative logic to inform the Tech Team if it's an Isolated Router/NAP Box Issue or a Massive Barangay-wide Fiber Cut.
Global Notification System

Engineered a global Top-Bar Notification Bell utilizing a custom Notification database model. It intercepts core system events (a customer expiring, a Cignal Addon requested by a user, or a router disconnecting) and pushes a notification directly to the Admin UI. Implemented "Mark All as Read" AJAX functionality, red-pulsing dots for unread alerts, and human-readable timestamps (e.g., "Today at 2:30 PM").

Auto-Suspend Cron Job Scripts

No more manual blocking. We converted the expiration tracking into custom Django Management Commands (python manage.py auto_suspend). These scripts are hard-wired into the Linux server's Cron Tab to run silently at exactly 12:01 AM every night, parsing the database for users whose due date has passed, and firing termination commands to the Mikrotik—plugging all revenue leaks.

August 22, 2026 (The Gametech Premium Redesign)

Complete Visual CSS Overhaul

We stripped out the generic, boring Bootstrap look and painstakingly wrote a custom theme.css framework to create the Gametech Premium UI, converting the software into an ultra-modern SaaS interface.

  • Vibrant CSS Gradients: Beautiful blue-to-purple diagonal gradient backgrounds (linear-gradient(135deg)) on headers, key actionable cards, and navigation items.
  • Avatar Generator: Customers no longer have boring gray placeholder icons. We built a Python string-parsing engine that extracts their First and Last initials and injects them into dynamically colored SVG circular profiles.
  • Apple-Style Glassmorphism: All dropdown menus, modal backgrounds, and floating sidebars utilize frosted-glass transparency effects via backdrop-filter: blur(16px).
  • Micro-Interactions & Animations: Forms fade in smoothly over 0.4 seconds, table rows lighten slightly when hovered over, and buttons utilize a subtle drop-shadow lift effect to make the system feel "alive".
  • Soft-Corner Aesthetic: Hard, ugly 90-degree edges were eradicated. Every single container, input field, button, and image now utilizes a unified border-radius: 16px.

August 20 - 21, 2026 (Security & Master Data Setup)

Role-Based Access Control (RBAC) Architecture

We locked down the entire system using Django's native permission groups. Every URL view (e.g., @permission_required) is now gated. Not everyone can see everything.

  • Administrators: Granted God-mode. They can delete customer profiles, view raw financial master logs, revert payments, and access the exact active sessions widget.
  • Technicians: Focuses strictly on engineering screens: the Network Manager, Live Monitoring, Sync Services, and Bulk Migration tools. They are locked out of modifying financial ledgers.
  • CSRs (Customer Service): A heavily restricted read-only environment. They can view customer profiles, answer tickets, and log simple payments, but they cannot delete structural data.
Master Data Management (CRUD Settings)

We engineered a standalone Settings module allowing Administrators to Create, Read, Update, and Delete organizational variables entirely via UI, without ever needing to touch backend code. This includes managing exactly which Barangay Locations exist in the system and classifying specific Account Types (e.g., Residential, Pisonet, Commercial).

Bulk Router Migration Technology

Added the highly complex Bulk Transfer feature for disaster recovery. If a Mikrotik router fails catastrophically or a barangay is upgraded to a new node, Admins can multi-select up to 100 customers, click "Transfer Router", and select the new hardware. The system's API engine autonomously logs into the old router, annihilates all associated PPPoE secrets, logs into the new router, and resurrects all profiles identically in seconds.

MAC Address Spoofing & History Tracking

To combat MAC spoofing and hardware cloning, we built a dedicated MAC History Database Log. The system continuously polls the router, and every time a customer connects via a new router device (differing MAC address), the system explicitly logs the old MAC, the new MAC, and the precise timestamp for forensic review.

August 13 - 19, 2026 (Advanced Financial Engineering & Portals)

The Customer End-User Portal

We broke ground on a dedicated, mobile-optimized Customer Portal (/portal/). By giving end-users the power to self-serve, we drastically reduced incoming support call volume.

  • Secure Login System: Customers log in securely using their Gametech Account ID and a pre-assigned PIN number.
  • Live Mikrotik Interfacing: The portal doesn't just read the database; it queries the Mikrotik API live to show the customer their exact connection status, IP, and router uptime.
  • Ledger Visibility: Customers can check their current expiration date, outstanding balance, subscription plan details, and a complete history of their past payments.
Statement of Account (SOA) Generation

Programmed a dynamic, PDF-ready Statement of Account (SOA) generation engine. It parses the customer's entire payment history, algorithmically calculates outstanding past-due balances, and formats everything onto a printable, highly professional Gametech letterhead for physical paper billing distribution across the barangays.

Rebates & Surgical Payment Rollbacks

Developed highly-sensitive financial adjustment tools. The Rebate System allows admins to surgically inject free days into a customer's account (e.g., granting a flat 3-day compensation for a major fiber outage) without messing up their billing cycle. The Rollback System was built to allow admins to delete a specific mistaken payment, forcing the system to recalculate the user's expiration date backward to the exact second it was before the payment was made.

Cignal Play & Cignal Box Add-ons Modules

Engineered an entirely separate relational database model to handle external Add-ons. Customers can click a button in their portal to request Cignal subscriptions, triggering an API call to the Live Addon Requests page for Admin review. Staff can assign Add-ons, establish secondary expiration dates (independent of internet), and track Add-on Payments separately from core internet revenue.

Geomap Visualizations & Plotting

We implemented a live Geomap Interface utilizing OpenStreetMap technology APIs. Administrators can drag and drop GPS pins for every single customer's physical NAP box/router location, rendering a massive visual representation of network density and geographic fiber routing.

August 11 - 12, 2026 (Genesis & Framework Initialization)

Total Destruction of Legacy PHP & Birth of Django

The project started with a massive architectural decision: the complete abandonment of the old, unscalable, insecure PHP codebase. We initialized a highly robust, modern Python & Django Framework.

  • Architected the core Django Apps (billing, network_manager, customer_portal).
  • Engineered the core Database Models (Customer, Payment, SubscriptionPlan, Router).
  • Executed a hyper-critical Data Migration. We extracted the raw legacy MySQL data and piped it flawlessly into the new Django ORM—preserving years of old customer records, plan assignments, and historical payment logs without a single loss of data.
Direct Mikrotik RouterOS 2-Way API Integration

This was the most technically impressive milestone of the entire project. We established a live, 2-way TCP API tunnel between the Django web server and the Gametech Mikrotik Core Router (192.168.88.2) utilizing the Python routeros_api package. This eliminated the need to ever use the Winbox application again by automating the following:

  • Automated Activations: When a CSR creates a new customer profile in the Billing System, Django instantly fires a command to the router, physically generating their PPPoE Secret, assigning their bandwidth profile, and generating their IP configuration in under 1 second.
  • Live Connection Polling: Built a real-time polling mechanism. The Django dashboard queries the Mikrotik's Active Connections list constantly, parsing the JSON data to display exactly who is currently consuming bandwidth, their assigned IP address, and their session uptime in seconds.
  • Automated Terminations: If an account is deleted or flagged as suspended in Django, an API kill-command is fired that instantly severs their active PPPoE session from the router and drops their firewall rule, shutting off their internet.
The Expiration Engine & Mathematical Logic

We coded the mathematical foundation of the entire billing cycle using Python datetime and timedelta logic. The system was programmed to track exact date and time expirations (e.g., dynamically adding 30 days to a due_date upon successful payment logging). We wrote the backend conditionals that automatically flags any account as Expired the second their internal clock passes the current server time, tying this directly into the Mikrotik suspension API mentioned above.

Network Manager Core Initialization

Established the network_manager Django application. This module serves as a hardware repository for managing multiple Mikrotik devices, securely storing their IP addresses, API ports, encrypted credentials, and node identifiers. This was built to ensure the Gametech billing software can infinitely scale across dozens of barangay nodes without requiring source code changes.

August 28 - 29, 2026 (Refinement & Polish) Latest Build

Staggered Payments

Completely transformed the payment processing engine to allow for Partial / Staggered Payments. If a customer cannot pay their full monthly due, the system now accepts exact cash fractions and precisely calculates the remaining balance and proportionate days of internet access.

We also built a Quick Pay Grid inside the customer profile, allowing staff to instantly select 1/4, 1/2, or 3/4 payment amounts without manual typing.

Error Correction (Transfer & Revert)

Mistakes happen. We built a Transfer Payment tool directly into the Payment Logs. If a staff member accidentally credits Customer A instead of Customer B, they can click "Transfer", select the correct customer, and the system automatically rolls back Customer A's expiration and ledger, and applies the payment cleanly to Customer B.

Sync Manager V2 & Suspicious Users

The Sync Manager was upgraded to become an auditing tool. It now cross-references the Mikrotik's PPPoE Secrets against the Django database to find discrepancies.

  • Identifies Orphaned Accounts (exist on router, not in system).
  • Flags Suspicious Accounts (profiles using 'default' instead of strict bandwidth profiles, missing standardized comments, or utilizing rogue characters).
  • Auto-formats all Mikrotik Comments to Full Name | Barangay for strict organizational hygiene inside Winbox.
Intelligent Customer Sorting

The Customer List was re-engineered to auto-sort by priority: Active → Pending → Suspended → Expired → Inactive → Pull Out. We added visual row highlighters (Amber for Expired, Gray for Suspended) so collections teams can easily identify targets.

Real-Time Admin Tracking

We created an ActiveUserMiddleware cache that tracks the exact millisecond any staff member navigates a page. The Recent Admin Logins widget on the dashboard now shows exactly who is actively clicking through the system right now, not just when they typed their password.

Core Logic Fixes

Fixed the Mikrotik Bridge Filter bug where suspended customers were not having their 'Drop' firewall rules properly removed upon payment reactivation. Cleaned up the background queue logic.

August 24 - 26, 2026 (Deployment & Monitoring)

Live Production Deployment

We took the system from a local development environment to a live, global production server. The architecture we built:

  • DigitalOcean Droplet: The core host server running Ubuntu Linux.
  • Docker & Docker Compose: We containerized the Django app, Gunicorn server, and Redis cache so the system runs in isolated, crash-proof environments.
  • Nginx Reverse Proxy: Hand-configured Nginx to serve static files and route traffic securely to the Docker containers.
  • GitHub Actions (CI/CD): We built an automated pipeline so that any time code is pushed to the main branch, the DigitalOcean server automatically pulls, rebuilds, and restarts without manual intervention.
Live Monitoring & Auto-Diagnostics

We built a massive Live Monitoring dashboard that acts as the network's nerve center.

  • Router Uplink Tracker: Pings the Mikrotik API every few seconds. If the router dies or loses internet, the entire system flags it as a "Network Outage".
  • Offline User Diagnostics: If a customer goes offline, the system cross-references other customers in their Barangay. It automatically diagnoses if the issue is an Isolated NAP Box Issue or a Barangay-wide Fiber Cut.
Global Notification System

Engineered a top-bar Notification Bell that alerts staff when a customer expires, a Cignal Addon is requested, or a router goes offline. Implemented "Mark All as Read" functionality, red-pulsing dots for critical alerts, and exact readable timestamps (e.g., "Today at 2:30 PM").

Auto-Suspend Engine Scripts

We converted the manual expiration checks into Django Management Commands (auto_suspend, auto_reconcile_routers). These commands are designed to run silently in the background (via cron) to terminate expired users at exactly midnight, ensuring zero revenue leakage.

August 22, 2026 (The Gametech Premium Redesign)

Complete Visual Overhaul

We stripped away the default Bootstrap look and built the Gametech Premium UI from scratch, transforming the billing system into an enterprise-grade SaaS interface.

  • CSS Gradients: Beautiful blue/purple gradient headers on every form and card.
  • Avatar Initials: Customer profiles no longer look boring; we built a dynamic engine that takes their first and last initials and generates a colored, circular profile picture.
  • Glassmorphism: Dropdowns and modals now use Apple-style frosted glass blur effects (backdrop-filter: blur(16px)).
  • Micro-Animations: Forms fade in smoothly, buttons lift slightly when hovered, and tables load with subtle grace.
  • Rounded Aesthetic: Hard edges were removed. All cards, input fields, and buttons now utilize a sleek 16px border-radius.

August 20 - 21, 2026 (Security & Master Data)

Role-Based Access Control (RBAC)

We locked down the entire system by implementing granular permissions. Not everyone can see everything anymore.

  • Administrators: Full God-mode access. Can delete customers, view financial master logs, and see who is logged in.
  • Technicians: Focuses strictly on Network Manager, Live Monitoring, and Sync Services. They cannot modify payment logs.
  • CSRs: Limited to viewing profiles, answering tickets, and logging basic payments.
Master Data Management

We built a settings module allowing Admins to Create, Read, Update, and Delete (CRUD) organizational variables without touching code. This includes managing Barangay Locations and classifying Account Types (e.g., Residential, Pisonet, Commercial).

Bulk Router Migration

Added the highly complex Bulk Transfer feature. If a Mikrotik router fails, or an area is upgraded, Admins can select 50 customers at once and click "Transfer Router". The system automatically logs into the old router, deletes their PPPoE secrets, logs into the new router, and recreates all their profiles instantly.

MAC Address History Tracking

To combat MAC spoofing and track hardware changes, we built a MAC History log. Every time a customer connects with a new router device (different MAC address), the system logs the old MAC, the new MAC, and the exact timestamp.

August 13 - 19, 2026 (Financial Engine & Portals)

The Customer Portal

We developed a dedicated, mobile-friendly Customer Portal (/portal/). We gave end-users the power to self-serve, drastically reducing support calls:

  • Secure login using their unique Account ID and PIN.
  • View exact live connection status and router uptime pulling straight from the Mikrotik.
  • Check their current expiration date, balance, and subscription plan details.
Statement of Account (SOA) Generation

Built a dynamic PDF-style Statement of Account generator. It pulls the customer's payment history, calculates outstanding balances, and formats it onto a printable, official letterhead for physical billing distribution.

Rebates & Rollbacks Engine

Developed the financial adjustment tools. The Rebate System allows admins to add free days to a customer's account (e.g., compensation for a 3-day fiber outage). The Rollback System allows admins to surgically reverse a specific payment, recalculating the expiration date backwards exactly as it was before the payment was made.

Cignal Play & Cignal Box Add-ons

Built an entire sub-module to handle external Add-ons. Customers can request Cignal subscriptions directly from their portal (triggering the Live Addon Requests API). Staff can assign add-ons, set secondary expiration dates, and track Add-on Payments completely separately from the core Internet Subscription.

Geomaps Visualization

We built a live Geomap Interface utilizing OpenStreetMap technology. Admin can drag and drop map pins for every customer's NAP box location, providing a visual representation of network density and physical fiber routing.

August 11 - 12, 2026 (Genesis)

Legacy Migration to Python/Django

The project began with a massive overhaul: abandoning the old, insecure, hard-to-maintain legacy PHP codebase. We initialized a completely modern, robust Python/Django framework.

  • Established the core Django App architecture (billing, network_manager, customer_portal).
  • Engineered the core Database Models (Customers, Payments, Subscription Plans, Routers, and Logs).
  • Executed a flawless data migration of all legacy MySQL tables into the new Django ORM—preserving years of customer history.
Direct Mikrotik RouterOS Integration

The most technically complex breakthrough: We successfully established a 2-way live API connection between the Django web server and the Gametech Mikrotik Router (192.168.88.2) using the official RouterOS API via Python routeros_api. This allowed us to build the following autonomous features:

  • Automated Activations: Creating a customer in the Billing System instantly fires an API command to the router, creating their PPPoE Secret, assigning their bandwidth profile, and generating their IP configuration. No more manual Winbox entry!
  • Live Connection Status: Built real-time pinging. The dashboard reads the Mikrotik's Active Connections list instantly, displaying exactly who is online, their assigned IP address, and their session uptime in seconds.
  • Automated Terminations: If an account is deleted or suspended, an API call is fired that instantly kicks (disconnects) their active PPPoE session from the router and disables their secret.
The Expiration Engine

We engineered the mathematical foundation of the billing cycle. The system was programmed to track exact date/time expirations (e.g., adding 30 days dynamically upon payment). We built the logic to automatically flag accounts as Expired, bridging this status directly to the Mikrotik suspension logic to cut off internet access precisely at the due date.

Network Manager Core

Established the network_manager module. This acts as a repository for managing multiple Mikrotik devices, storing their IP addresses, API ports, and credentials securely, allowing the billing system to scale across multiple barangay nodes in the future.
